# Leonardo QA

Only Leonardo is active; historical provider enum values remain for records. Sync API uses `remove-bg`, car/shadow, transparent WebP, private+ephemeral flags. Server plan chooses preview/auto; source is a short-lived signed URL, background composition uses packaged artwork rather than provider studio generation. Adapter validates bounded JSON, result URL, download length/content type, full image/alpha and safe pixels; redirects are rejected and transient downloads retry within one deadline.

Executed without paid traffic: provider error/402/429/timeouts/malformed result/missing alpha/non-car assertions, request shape and tier resolution, source validation before provider, durable cutout reuse and lifecycle telemetry. Reproduction BUG-003: first successful provider response could not be staged; second attempt paid again. Two mock successful calls for one logical job were observed. Five failed staging attempts can amplify successful paid calls up to the attempt budget; SQS replays/outbox transport exhaustion require separate bounds. No live currency estimate is asserted because actual price/model billing was not supplied.

Actual provider endpoint availability, signed-source fetching, model quality, real image semantics, per-generation invoices, hard crash after provider success, rate-limit bursts and credit exhaustion are BLOCKED. Generation ID is not durably persisted before cutout staging, and there is no true idempotency/reconciliation call. A syntactically valid arbitrary HTTPS result host is accepted; destination restriction/SSRF policy needs an isolated adversarial adapter test before relying on provider responses as trustworthy.
